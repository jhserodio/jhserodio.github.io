<p>The first contact with collections, it’s aways a hard thing for new developers, we take a principle the data types, and start to create diferent kind of collections about then, List are simple to understand, but when we thing about the types it’s, the memory usage, or use compounding types like structs with lists, everything turning more complicated.</p><p>Here in this article, we will see the about Lists, Structs, Pointers with a diferent Eyes, we will try to understand useful algorithms for in the carreer or studies, training our skills to adapt to the market, the intention it’s every time to understand better the concepts about software develpment. After this we well star to see about Sort Algorithms, but it’s will be see only the first steps in ordering algorithms.</p><p>Ow yet, we will use C and Rust, it’s a way to understand why it’s good to understand the concepts about memory management with two diferents architetucres (pointers and ownerships) and pratice to become a better developer.</p><h3>1. Vectors and Arrays</h3><p>A Vector (or array) is a data structure that stores a collection of elements of the same data type in a single, contiguous block of memory. It is the most hardware-friendly structure in existence. By placing data strictly side-by-side in RAM, the CPU can fetch multiple elements into its ultra-fast L1 cache simultaneously. This physical characteristic is what allows O(1) random access time, which is the absolute foundation for divide-and-conquer algorithms in computer science.</p><p><strong>O(log n) searching with Binary Search</strong></p><p>To demonstrate why contiguous memory is so powerful, we will implement a Binary Search. This algorithm cuts a sorted dataset in half iteratively to find a target value. It relies entirely on the ability to calculate a memory offset (mid) and jump instantly to that exact physical location in the array. This is widely used in database indexing and low-level system lookups.</p><pre>#include &lt;stdio.h&gt;<br><br>// We pass the contiguous array and its size<br>int binary_search(int arr[], int size, int target) {<br>    int left = 0;<br>    int right = size - 1;<br><br>    while (left &lt;= right) {<br>        // We calculate the middle index to avoid integer overflow<br>        int mid = left + (right - left) / 2;<br><br>        // O(1) memory access: we jump directly to the &#39;mid&#39; offset<br>        if (arr[mid] == target) {<br>            return mid; <br>        }<br><br>        // The Directional Comparator (Signum logic)<br>        if (arr[mid] &lt; target) {<br>            left = mid + 1;<br>        } else {<br>            right = mid - 1;<br>        }<br>    }<br>    return -1; // Target not found<br>}</pre><p>In Rust, the physical memory layout of a Vec or array is identical to C, but the way we interact with it introduces Ownership and Borrowing. Instead of passing a raw pointer to the first element and an integer for the size, we pass a <em>slice</em> (&amp;[i32]). A slice is a safe, borrowed view into a contiguous block of memory. It knows its own length, preventing buffer overflows at compile time without sacrificing the raw performance of O(1) memory access.</p><pre>// We borrow a slice of the array (&amp;[i32]), meaning we don&#39;t take ownership, <br>// we just look at the memory safely.<br>pub fn binary_search(arr: &amp;[i32], target: i32) -&gt; Option&lt;usize&gt; {<br>    let mut left = 0;<br>    let mut right = arr.len();<br><br>    while left &lt; right {<br>        let mid = left + (right - left) / 2;<br><br>        if arr[mid] == target {<br>            return Some(mid);<br>        }<br><br>        if arr[mid] &lt; target {<br>            left = mid + 1;<br>        } else {<br>            right = mid;<br>        }<br>    }<br>    None<br>}</pre><h3>2. Structs</h3><p>A struct is a custom data type that allows you to group different scalar variables into a single, contiguous block of memory. It is not an abstract &quot;object&quot;; it is a physical map of bytes. In market applications like game engines (physics calculations) or computational geometry, structs group related spatial data. But data without behavior is useless. We often need to mutate the state of these structs, which means we must pass their memory addresses to functions to act as &quot;methods.&quot;</p><p><strong>Attaching behavior to grouped spatial data</strong></p><p>Imagine we are building a physics simulation and we have a 2D vector representing a coordinate. We need a function to translate (move) this coordinate. To modify the original struct in C, we cannot pass it by value (which would create a heavy, useless copy). We pass a pointer to the struct and use the -&gt; operator to dereference and modify its internal memory layout.</p><pre>#include &lt;stdio.h&gt;<br><br>// Grouping X and Y contiguously in memory<br>typedef struct {<br>    int x;<br>    int y;<br>} Vector2D;<br>// Simulating a &quot;method&quot; by passing the struct&#39;s memory address<br>void translate(Vector2D *v, int dx, int dy) {<br>    // The &#39;-&gt;&#39; operator dereferences the pointer and accesses the specific byte offset<br>    v-&gt;x += dx; <br>    v-&gt;y += dy;<br>}<br>int main() {<br>    Vector2D player_pos = {10, 20};<br>    <br>    // We pass the physical address of the struct to mutate its state<br>    translate(&amp;player_pos, 5, -3); <br>    <br>    return 0;<br>}</pre><p>In Rust, we don’t have to simulate methods using loose functions and raw pointers. Rust allows us to attach behavior directly to the struct using impl blocks. Under the hood, this compiles down to the exact same machine code as the C example. The magic happens with &amp;mut self, which is fundamentally a safe, mutable pointer to the struct. The Borrow Checker guarantees that while translate is mutating the struct, no other thread or function can read or write to it, completely eliminating data races.</p><pre>struct Vector2D {<br>    x: i32,<br>    y: i32,<br>}<br><br>// We implement behavior directly onto the data layout<br>impl Vector2D {<br>    // &amp;mut self is a mutable borrow of the struct&#39;s memory<br>    fn translate(&amp;mut self, dx: i32, dy: i32) {<br>        self.x += dx;<br>        self.y += dy;<br>    }<br>}<br>fn main() {<br>    let mut player_pos = Vector2D { x: 10, y: 20 };<br>    <br>    // The compiler automatically passes &amp;mut player_pos under the hood<br>    player_pos.translate(5, -3);<br>}</pre><h3>3. Pointers</h3><p>Pointers are the bridge between abstract logic and the physical hardware. They are essential for handling dynamic heap allocation when the size of our data is not known at compile time, passing large structures without duplicating memory, and manipulating raw bytes like strings. To understand them, we must visualize them:</p><ul><li><strong>Memory Inference (</strong><strong>&amp;):</strong> Extracts the physical memory address of a variable. <em>Analogy: Looking up the exact street address of a house.</em></li><li><strong>Memory Dereference (</strong><strong>*):</strong> Travels to the address to read or modify the value inside. <em>Analogy: Going to the street address to place or remove a package inside the house.</em></li><li><strong>Pointer to Pointer (</strong><strong>**):</strong> Stores the address of another pointer. <em>Analogy: A piece of paper that holds the location of a safe, and inside that safe is the actual street address of the house.</em></li></ul><p><strong>Navigating dynamic arrays, structs, and strings</strong></p><p>Pointers become absolutely mandatory when our programs must adapt at runtime. If we need an array that grows, a collection of our Vector2D structs, or a simple text string, we cannot rely on the stack. We must ask the operational system for memory on the Heap (malloc), and the system returns a pointer to the start of that block. In C, a string is literally just a pointer to the first character of an array (char *) that ends with a null byte (\0).</p><pre>#include &lt;stdio.h&gt;<br>#include &lt;stdlib.h&gt;<br>#include &lt;string.h&gt;<br><br>typedef struct {<br>    int x;<br>    int y;<br>} Point;<br><br>int main() {<br>    int dynamic_size = 5;<br>    // 1. Array without a defined size at compile time (Dynamic Array)<br>    // We get a pointer to a heap block large enough for 5 integers.<br>    int *dynamic_array = (int *)malloc(dynamic_size * sizeof(int));<br>    dynamic_array[0] = 42; <br>    // 2. An Array of Structs<br>    // We allocate memory for 5 Point structs continuously.<br>    Point *struct_array = (Point *)malloc(dynamic_size * sizeof(Point));<br>    struct_array[0].x = 10;<br>    struct_array[0].y = 20;<br>    // 3. A String (Pointer to characters)<br>    // Allocating memory for a string of up to 50 characters.<br>    char *text_string = (char *)malloc(50 * sizeof(char));<br>    strcpy(text_string, &quot;Memory is just an array of bytes&quot;);<br>    // In C, YOU are responsible for returning the memory to the OS.<br>    free(dynamic_array);<br>    free(struct_array);<br>    free(text_string);<br>    return 0;<br>}</pre><p>When we see pointers manually managing heap allocations in C, we need to understand how Rust handles this exact same hardware reality through Ownership. In C, a pointer is just an address — it doesn’t care if the memory was already freed, leading to catastrophic bugs. In Rust, dynamic arrays (Vec), arrays of structs (Vec&lt;Point&gt;), and strings (String) are smart structures that inherently <em>own</em> their heap pointer. They allocate the memory, and when they go out of scope, they automatically free it.</p><p>When you need to pass these collections to an algorithm — like a sorting function — you do not pass raw pointers. Instead, you create a <em>mutable borrow</em> (&amp;mut). A mutable borrow allows the algorithm to dereference and swap the data inside the heap, but the Borrow Checker mathematically guarantees that the memory will not be corrupted or freed while the algorithm is using it. This strict separation between who <em>owns</em> the memory and who is <em>borrowing</em> it is what we need to write our sort algorithms safely.</p><pre>struct Point {<br>    x: i32,<br>    y: i32,<br>}<br><br>fn main() {<br>    // 1. Array without a defined size (Dynamic Array)<br>    // Rust&#39;s Vec owns the heap pointer and automatically frees it.<br>    let mut dynamic_array: Vec&lt;i32&gt; = Vec::new();<br>    dynamic_array.push(42);<br>    // 2. Array of Structs<br>    // We can dynamically push custom structs into a Vec.<br>    let mut struct_array: Vec&lt;Point&gt; = Vec::new();<br>    struct_array.push(Point { x: 10, y: 20 });<br>    // 3. A String<br>    // String is an owned, growable heap-allocated buffer.<br>    let text_string = String::from(&quot;Memory is just an array of bytes&quot;);<br>    // BORROWING IN PRACTICE: <br>    // To sort or modify the dynamic array, we don&#39;t pass raw pointers. <br>    // We pass a mutable reference to a slice of the array.<br>    let slice_to_sort: &amp;mut [i32] = &amp;mut dynamic_array[..];<br>    <br>    // We can safely mutate the slice. Rust guarantees the memory is valid.<br>    slice_to_sort[0] = 99;<br>}</pre><h3>4. Introduction to Sorting</h3><p>Once we understand how data is contiguously allocated in memory — whether on the stack or the heap — the next step is organizing it. Data without order is extremely expensive to search. Sorting is the computational process of arranging memory blocks in a specific sequence, allowing algorithms like Binary Search to operate in O(log n) time. At its core, sorting is an exercise in memory manipulation: reading values, evaluating their mathematical relationship (Signum), and overwriting bytes in RAM.</p><p>Here, we will look at the three foundational sorting algorithms. For each one, we will examine the theory, trace the memory states through a table test, and write the bare-metal implementation in C and the memory-safe implementation in Rust.</p><h4>4.1 Bubble Sort</h4><figure><img alt="" src="/article-images/table-test-bubble-sort.webp" /><figcaption>Buble Sort Table Test</figcaption></figure><p>Bubble sort is the simplest sorting algorithm. It repeatedly steps through the array, compares adjacent elements, and swaps them if they are in the wrong order. This process bubbles the largest element to the end of the array. While it is rarely used in production software due to its O(n²) inefficiency, it is the perfect educational tool to demonstrate array iteration and local memory swaps.</p><p><strong>Adjacency swapping in C and Rust</strong></p><p>In C, we use nested loops to iterate through the array and manually swap the values in memory using a temporary variable. We are directly manipulating the memory offsets of the array.</p><pre>void bubble_sort(int arr[], int n) {<br>    for (int i = 0; i &lt; n - 1; i++) {<br>        // The last &#39;i&#39; elements are already sorted, so we don&#39;t check them<br>        for (int j = 0; j &lt; n - i - 1; j++) {<br>            if (arr[j] &gt; arr[j + 1]) {<br>                // Direct memory swap<br>                int temp = arr[j];<br>                arr[j] = arr[j + 1];<br>                arr[j + 1] = temp;<br>            }<br>        }<br>    }<br>}</pre><p>In Rust, we don’t pass the array as a raw pointer. We pass a mutable slice (&amp;mut [i32]). To swap elements, we could write the temporary variable logic manually, but Rust provides a built-in .swap() method on slices. This method temporarily bypasses the strict rule against having two mutable references to the same array by safely executing the memory swap under the hood.</p><pre>pub fn bubble_sort(arr: &amp;mut [i32]) {<br>    let n = arr.len();<br>    for i in 0..n {<br>        for j in 0..(n - i - 1) {<br>            if arr[j] &gt; arr[j + 1] {<br>                // Safe, in-place memory swap provided by the standard library<br>                arr.swap(j, j + 1);<br>            }<br>        }<br>    }<br>}</pre><h4>4.2 Selection Sort</h4><figure><img alt="" src="/article-images/table-test-selection-sort.webp" /><figcaption>Selection Sort Table Test</figcaption></figure><p>Unlike Bubble Sort, which swaps data constantly, Selection Sort scans the unsorted portion of the array to find the absolute minimum value, and then swaps it directly into its final sorted position. In the real world, this algorithm is actually useful in embedded hardware systems (like Flash memory or EEPROM). In these environments, memory write operations physically degrade the hardware and are very slow, whereas read operations are fast. Selection Sort minimizes the number of memory writes to exactly O(n).</p><p><strong>Minimizing memory write cycles</strong></p><p>In C, we keep track of the min_idx (the memory offset of the smallest value found so far) and only perform the overwrite operations once the inner loop has finished scanning.</p><pre>void selection_sort(int arr[], int n) {<br>    for (int i = 0; i &lt; n - 1; i++) {<br>        int min_idx = i;<br>        <br>        // Scan the remaining memory blocks for a smaller value<br>        for (int j = i + 1; j &lt; n; j++) {<br>            if (arr[j] &lt; arr[min_idx]) {<br>                min_idx = j;<br>            }<br>        }<br>        <br>        // Perform a single swap (write cycle) per pass<br>        if (min_idx != i) {<br>            int temp = arr[i];<br>            arr[i] = arr[min_idx];<br>            arr[min_idx] = temp;<br>        }<br>    }<br>}</pre><p>In Rust, the logic remains identical. We iterate over the mutable slice, find the index of the minimum value, and use the .swap() method. The borrow checker ensures that while we are reading the array to find min_idx, we aren&#39;t accidentally mutating it elsewhere.</p><pre>pub fn selection_sort(arr: &amp;mut [i32]) {<br>    let n = arr.len();<br>    for i in 0..n {<br>        let mut min_idx = i;<br>        <br>        for j in (i + 1)..n {<br>            if arr[j] &lt; arr[min_idx] {<br>                min_idx = j;<br>            }<br>        }<br>        <br>        if min_idx != i {<br>            arr.swap(i, min_idx);<br>        }<br>    }<br>}</pre><h4>4.3 Insertion Sort</h4><figure><img alt="" src="/article-images/table-test-insertion-sort.webp" /><figcaption>Insertion Sort Table Test</figcaption></figure><p>Insertion Sort builds a sorted sequence one element at a time. It picks the next element and shifts all larger elements to the right to make room for it. While it is technically O(n²), it is incredibly fast for small datasets and memory segments that are already mostly sorted. Because of its extreme efficiency with CPU caches and small arrays, it is used in the real world as the base case for complex hybrid algorithms like Timsort (used in Python and Java) and Introsort (used in C++ and Rust standard libraries).</p><p><strong>Shifting contiguous memory blocks</strong></p><p>In C, we pull the current value out into a temporary variable (key). We then compare it backwards, shifting elements one byte offset to the right until we find the correct memory slot to drop our key into.</p><pre>void insertion_sort(int arr[], int n) {<br>    for (int i = 1; i &lt; n; i++) {<br>        int key = arr[i]; // Store the value we want to position<br>        int j = i - 1;<br>        <br>        // Shift elements to the right to clear a space<br>        while (j &gt;= 0 &amp;&amp; arr[j] &gt; key) {<br>            arr[j + 1] = arr[j];<br>            j = j - 1;<br>        }<br>        <br>        // Drop the value into the cleared memory slot<br>        arr[j + 1] = key;<br>    }<br>}</pre><p>In Rust, the implementation is conceptually the same, but we have to be mindful of types. Rust is very strict about preventing negative index access (which can lead to segmentation faults in C). Because array lengths and indices are unsigned integers (usize), j cannot go below zero. We must structure our loop safely to handle the boundaries of the slice without underflowing the unsigned integer.</p><pre>pub fn insertion_sort(arr: &amp;mut [i32]) {<br>    for i in 1..arr.len() {<br>        let key = arr[i];<br>        let mut j = i;<br>        <br>        // We check j &gt; 0 first to prevent unsigned integer underflow, <br>        // then we check if the previous element is greater than our key.<br>        while j &gt; 0 &amp;&amp; arr[j - 1] &gt; key {<br>            arr[j] = arr[j - 1];<br>            j -= 1;<br>        }<br>        <br>        arr[j] = key;<br>    }<br>}</pre><h3>Conclusion</h3><p>Understanding collections and sorting algorithms is not about memorizing syntax to pass a whiteboard interview. It is about fundamentally aligning your mental model with the physical reality of the hardware.</p><p>When you write algorithms in C, the machine is completely exposed. You are forced to confront memory addresses, contiguous byte allocations, and manual data swaps. C gives you the raw power to manipulate the CPU and RAM exactly as you see fit, but it demands absolute discipline to avoid destroying the system.</p><p>When you translate those exact same bare-metal concepts into Rust, you witness the evolution of software engineering. Rust does not hide the hardware behind a Garbage Collector like higher-level languages do. Instead, it enforces strict mathematical rules over your memory through Ownership and Borrowing. By studying both, you are not just learning two different syntaxes — you are mastering the physics of computation. You learn the <em>how</em> in C, and the <em>safe architectural design</em> in Rust.</p><p>The next time you call .sort() on a dynamic array in a production environment, you will no longer see it as compiler magic. You will see the CPU cache fetching contiguous memory blocks, the pointers mapping the boundaries, and the algorithm shifting bytes to minimize physical write cycles.</p><p>Take these implementations, type them out manually, and run them. Break the bounds of the arrays in C to see the segmentation faults, and fight the Borrow Checker in Rust to understand why it stops you. Build your engineering knowledge on the solid rock of memory management, and every complex system architecture you encounter in your career will make perfect sense.</p><img src="https://medium.com/_/stat?event=post.clientViewed&referrerSource=full_rss&postId=fbe39d063197" width="1" height="1" alt="">
